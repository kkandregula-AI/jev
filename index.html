20 agentic use cases of TypeSafe AI’s Jev

TypeSafe AI's Jev is a System One model. It doesn't chat or write code. You hand it an agent's state and a set of typed questions, and it returns decisions with calibrated probabilities — so the thousands of small judgments inside an agent loop stop costing a full LLM call each.

01 · How Jev works

Three typed primitives

Each call sends one state (text or JSON) plus a dictionary of questions. All questions are answered in parallel against the same state, in a single request.

CHOICE

Pick one option. You describe each option in criteria; Jev returns a probability for every option, plus confidence.

{"dept": {"type":"choice",
  "instructions":"Which team handles this?",
  "criteria":{
    "billing":"Charges, refunds, invoices",
    "tech":"App errors, login issues",
    "sales":"Plans, upgrades, pricing"}}}

SCORE

Rate the state on an ordered rubric. Each level in criteria is described in words; Jev returns a probability per level and a score between them.

{"difficulty": {"type":"score",
  "instructions":"How hard is this task?",
  "criteria":[
    "One-line change, no reasoning",
    "Several files, clear approach",
    "Design decisions, many unknowns"]}}

NOUL

A yes/no question. Returns one number from 0 to 1: the probability the answer is yes. Optional criteria define what counts as yes and no.

{"irreversible": {"type":"noul",
  "instructions":"Would this command destroy data?",
  "criteria":{
    "true":"Deletes, overwrites or resets data",
    "false":"Only reads, lists or inspects"}}}
The rubric is what you write: instructions (the question) and criteria (what each answer means). Jev reads the state against them. Trained with RLCD (Reinforcement Learning for Calibrated Decisions), so higher confidence should track higher accuracy. The payoff: your code, not the model, decides what happens at each probability. 02 · One pass vs token stream

Why it's fast

The same customer message goes to both. The LLM has to be told the format in its prompt, writes its answer token by token, and you parse the JSON out of the text. Jev gets the message as state plus typed questions whose criteria are the rubric (highlighted), and returns every answer with probabilities in one pass. So what decides Jev's answer?three layers
1 · Your question rubricThe highlighted instructions and criteria. Jev reads the message against each description you wrote, so vague criteria give vague answers. TypeSafe advises concrete, situational wording (“money at risk right now”) over abstract degrees (“high”).
2 · Jev's trained judgementHow strongly the message matches each description comes from what the model learned in training. TypeSafe trains it with RLCD so confidence tracks accuracy: answers given at 0.9 should be right about 9 times in 10. That is what makes the numbers usable as thresholds.
3 · Your action rubricJev never acts. The thresholds in ③ are yours: pick them by testing on your own past tickets, then tune.

03 · Confidence gating

Code draws the line

Every Jev answer carries a probability, so you pick a threshold. Above it, the agent acts automatically; below it, the call goes to a stronger model or a human. This is how the auto-approve and risk-gating hooks work.

The jev-auto-approve hook uses p ≥ 0.95 and, in its published calibration, approved 0 of 8 state-changing commands. Drop the slider and watch risky commands slip through.

07 · Choosing

Jev or LLM?

The short rule: if the answer is a pick from a list you already know, ask Jev. If the answer has to be written or reasoned out, ask an LLM. Most real agents use both.

Use Jev when…

  • The answers are fixed. A category, yes/no, a level on a scale, which model or tool.
  • It happens often. Thousands of times a day, so ~13× speed and ~1/22 cost add up.
  • Something is waiting. A user in chat, a browser agent between clicks, a check before every command.
  • You need to know how sure it is. Calibrated probabilities let code auto-act above a threshold.
  • Code acts on it directly. No parsing, no broken JSON, no retries.

Use an LLM when…

  • The output is text. A reply, a summary, code, a plan, an email.
  • It needs multi-step reasoning. Working out why, weighing trade-offs, planning the next move.
  • The categories aren't known yet. “What are people complaining about?” rather than “which of these 12?”
  • It's rare or one-off. Writing and tuning criteria isn't worth it.
  • Accuracy beats speed and cost. On Banking77, Claude Opus 5 scored 84.4% vs Jev's 81.0%.

09 · Read before you ship

Honest limits

Schema-safe ≠ correct

Typed output removes parse errors, not wrong answers. Calibrate thresholds on your own traffic before trusting auto-actions.

Headline speed-ups are vendor evals

The 193.6× faster / 444.6× cheaper figures come from TypeSafe's own workflow evals, which it says sit at the high end of real-world gains.

Bounded questions only

Jev answers closed-set questions. Anything that needs planning, writing or open-ended reasoning stays with the LLM.

Hosted, not local

Jev's weights are closed. For on-prem, open projects like Laya and kev implement the same /v1/systemone interface.
